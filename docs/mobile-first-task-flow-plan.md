# GotheWord 移动端首屏与学习流程适配技术方案

状态：待实施
审计日期：2026-07-26
关联范围：`app/GotheWordApp.tsx`、`tests/mobile.spec.ts`
关联 Linear：POR-11 / GotheWord MVP 闭环

## 1. 结论

当前页面已经解决了横向溢出、基础触控尺寸和部分视觉问题，但移动端仍存在“能显示，不好完成任务”的缺口：

- 首页先展示无操作价值的完成态/空状态卡片，真正可执行的主任务在首屏之外。
- 单词记忆页把单词、三个例句和完成按钮纵向串联，导致用户每个词都要重复滚动。
- 320×720 下完成报告的指标和操作按钮不能同时进入首屏。
- 页面通过同一路由切换首页、学习、反馈和报告，没有明确的滚动恢复策略；从较深位置开始学习时可能继承旧 `scrollY`。
- 现有移动端测试只证明“无横向溢出、元素存在、触控尺寸合格”，不能证明主任务无需滚动即可完成。

本轮不改后端、Supabase API、数据库、学习状态类型或复习算法。适配只重排现有数据和现有交互。本文最初基于旧 UI 依赖编写；当前通用 UI 已迁移到仓库内的 `@gotheword/pencil-pup-ui`。

## 2. 现场审计

### 2.1 审计方式

在本地当前源码上使用真实 Chromium 移动视口检查：

- 320×720：最小验收视口。
- 390×844：常见 iPhone 视口。
- 使用测试用户本地状态进入今日首页、单词记忆、正确反馈和学习报告。
- 同时运行现有 `npm run test:mobile`，用于对比当前自动化覆盖范围。

### 2.2 当前结果

| 页面 / 状态 | 视口 | 页面高度 | 首屏结果 |
| --- | ---: | ---: | --- |

| 今日首页：无到期复习、有新词任务 | 320×720 | 2197px | “暂无到期复习”位于 y=734–782；“学习新单词”位于 y=1035–1083，均不可见 |

现有移动端测试 6/6 通过，但以上问题仍然存在，说明测试缺少“首屏主操作可达”和“阶段切换滚动归位”断言。

## 3. 页面优先级

移动端不追求所有页面完全没有滚动。不同页面使用不同标准：

### 3.1 任务页：主操作首屏可达

适用于：

- 今日首页的当前优先任务
- 单词记忆
- 单词测试
- 答题反馈
- 完成报告

要求：

- 当前任务上下文、必要内容和唯一主操作在 320×720 首屏内可见。
- 长文本允许内部内容自然增长，但主操作必须保持可达。
- 切换任务阶段后从页面顶部开始，不继承上一阶段的滚动位置。

### 3.2 信息页：首屏提供有效摘要

适用于：

- 学习统计
- 设置
- 首次目标设置

要求：

- 首屏显示页面标题和至少一组有效信息或可执行设置。
- 详细图表、历史数据和破坏性操作允许继续向下滚动。

### 3.3 信息保留顺序

1. 当前任务与进度：学习/复习类型、当前第几个词、计时与暂停。
2. 核心学习信息：单词、中文释义、名词冠词/复数或动词原形。
3. 主要例句：至少一个德中例句及发音。
4. 主操作：开始、继续、完成、返回。
5. 次要内容：额外例句、完整统计、自由学习入口。
6. 装饰内容：大面积留白、重复说明、移动端 Footer/Time 装饰。

## 4. 复用与能力边界

### 4.1 后端与数据流

直接复用当前数据：

- `dueWords`、`reviewBatch`：决定复习是否是当前优先任务。
- `remainingGoal`、`todayStats.goalNewLearned`：决定新词任务是否需要展示。
- `session.phase`、`session.memoryIndex`、`session.feedback`：决定学习阶段和滚动归位时机。
- `report`：继续提供完成数、答题数、正确率、学习时长和薄弱词。

不新增接口，不增加仅供移动端使用的字段，不复制学习状态。

### 4.2 `@gotheword/pencil-pup-ui`

已核对当前安装版本 1.2.3 的 README、`AI_USAGE.md` 和导出类型，可直接复用：

- `Button`：主操作、次操作、发音操作。
- `Card`：任务区、单词区、报告摘要区。
- `Collapse`：收纳次要例句，保留完整内容。
- `Progress`：每日目标、学习进度和答题连续正确进度。
- `Tabs`、`Tag`、`Title`、`Modal`：继续使用现有公开 API。

不新增本地 Button/Card/Collapse，不引入 shadcn 或其他 UI 库，不覆盖组件库内部 class。原生 `main`、`section`、`article`、`dl`、`div` 只承担语义和布局。

## 5. 详细适配方案

### 5.1 今日首页：按“下一步动作”排序

当前问题位于 `app/GotheWordApp.tsx` 的 `homeContent`：复习卡永远排在新词卡之前，即使到期复习为 0，也会用一张大卡占据首屏。

改为由现有状态决定单一主任务：

1. `dueWords.length > 0`
   - 首屏主卡：到期复习。
   - 保留批次数量、剩余数量和“开始今日复习”。
   - 新词目标降为次级摘要，位于主任务之后。
2. `dueWords.length === 0 && remainingGoal > 0`
   - 首屏主卡：今日新词。
   - “复习已清空”改为主卡内的紧凑状态提示，不再单独占用一张 Card。
   - “学习新单词”必须在 320×720 首屏内完整可见。
3. `dueWords.length === 0 && remainingGoal === 0`
   - 使用一张完成态 Card 合并“复习已清空”和“今日目标已完成”。
   - 首屏保留今日摘要；自由学习作为次操作，不抢占主要完成信息。

首页标题在手机上缩短为一行任务导向文案，较长的鼓励说明移到主任务卡中或在 `sm` 以上显示。桌面端可继续保留完整问候。

### 5.2 今日数据：减少重复 Card 内边距

当前四项指标各使用一张 Card。对于只有“标签 + 数值 + 单位”的信息，四次 Card 内边距会放大纵向空间。

改为：

- 使用一个 `Card` 包含一个语义 `dl`。
- `dl` 在 320px 保持 2×2 网格；不再回退到四行单列。
- 四项数据仍全部显示：新学、复习、时长、连续学习。
- 桌面端可在同一结构上扩展为 4 列，不维护两套 DOM。

这不是新增统计卡组件，只是页面内语义布局。

### 5.3 单词记忆：一屏完成一个词

当前结构为“单词 Card + 例句 Card + 底部按钮”，并固定展示三个例句。

改为单个学习 Card：

- 上部：词性 Tag、单词、发音、中文释义、冠词/复数。
- 中部：始终展示第一个德中例句和发音。
- 次要例句：若需要收纳另外两个例句，应先在 `pencil-pup-ui` 增加可复用的折叠组件，标题为“更多例句（2）”。
- 底部：继续使用 `pencil-pup-ui` `Button` 作为“我记住了”主操作。

移动端主操作区使用页面级 `sticky bottom-0` 布局，并预留 `env(safe-area-inset-bottom)`；Button 本身不复制、不封装、不覆盖内部样式。内容区增加等量底部空间，避免主操作遮挡例句。

320×720 的首屏最低保留：

- 学习 Header 与进度
- 单词和释义
- 名词复数/动词信息
- 一个完整例句
- “我记住了”主操作

额外例句仍可访问，但不再强迫每个词都滚动三段内容。

### 5.4 测试、反馈与错误反馈

测试页当前结构基本满足移动端：

- 保留单词、发音、四个选项和“忘记了”。
- 320px 继续使用单列选项；360px 以上是否两列由实际最长中文选项验证，不以宽度为唯一条件。

反馈页：

- 正确反馈保持当前紧凑结构。
- 错误反馈优先显示正确答案和一个例句；“继续”保持 sticky 主操作。
- 不在首屏重复解释完整记忆算法，较长说明降为辅助文本。

### 5.5 完成报告：合并指标，突出返回路径

当前报告使用四张 Card，320px 下产生四行并把按钮推到首屏外。

改为：

- 使用一张 `Card` + 2×2 `dl` 展示四项指标。
- 报告标题、说明、指标摘要和“返回首页”在 320×720 首屏内完整可见。
- “自由学习更多单词”保留为次操作，可位于主操作之后。
- 薄弱词存在时保留薄弱词 Card；它属于次级详情，允许向下滚动。
- 移动端隐藏纯装饰 Footer，`sm` 以上继续显示。

### 5.6 滚动与焦点管理

当前首页、学习、反馈、报告都在同一路由内条件渲染，浏览器不会自动执行路由级滚动恢复。

增加页面阶段键：

```text
home:<activeTab>
session:<sessionId>:<phase>:<memoryIndex>:<feedbackState>
report:<mode>
```

当阶段键变化时：

- 将窗口滚动到新页面 `main` 顶部。
- 将焦点移动到新阶段的主标题，标题使用 `tabIndex={-1}`。
- 焦点移动不播放平滑滚动；遵循 `prefers-reduced-motion`。
- 仅在阶段变化时执行，不因计时器每秒更新而重复滚动。

这部分属于 UI 导航状态，不新增 React 业务状态，也不改会话持久化结构。

### 5.7 统计、设置与首次目标

这些页面允许自然滚动，但需要降低首屏空耗：

- 手机端页面标题和说明缩短垂直间距。
- 统计概览使用单 Card 2×2 `dl`；完整七日图表继续在下方展示。
- 设置页首屏显示每日目标 Radio；“清除学习记录”保留在下方。
- 首次目标页优先显示目标 Card 和开始按钮；大段品牌说明在手机上压缩，桌面保持现有双栏。

## 6. 不做的改动

- 不为了布局修改 Supabase schema、API 或 `learning.ts`。
- 不新增移动端专用学习状态。
- 不通过 `window.innerWidth` 分叉两套业务渲染。
- 不使用 `position: fixed` 覆盖页面内容；优先使用可参与文档流的 sticky 区域。
- 不隐藏单词释义、复数、核心例句或报告核心指标。
- 不对 `pencil-pup-ui` 内部 DOM、class、padding 或颜色写页面级覆盖规则。
- 不新增本地通用 UI 组件。

## 7. 自动化验收

### 7.1 新增断言

在 `tests/mobile.spec.ts` 增加：

1. `expectPrimaryActionInInitialViewport`
   - 目标按钮 `top >= 0`
   - 目标按钮 `bottom <= innerHeight - 8`
   - 不与 sticky 操作区或浏览器安全区重叠
2. `expectStageStartsAtTop`
   - 首页深处进入学习后 `scrollY <= 1`
   - 单词切换、记忆转测试、反馈转报告后同样归位
3. `expectCriticalContentVisible`
   - 单词、释义、第一个例句和主操作同时可见
   - 报告标题、四项指标和“返回首页”同时可见
4. 保留现有：
   - 无横向溢出
   - 触控目标
   - Card 对比度
   - 键盘导航和 reduced-motion

## 8. 完成标准

- 320×720 和 390×844 下，首页当前优先任务的主操作无需滚动即可完整看到。
- 单词记忆页无需滚动即可完成“看词 → 看一个例句 → 我记住了”。
- 额外两个例句仍可通过 `Collapse` 查看并朗读。
- 320×720 下完成报告的标题、四项核心指标和“返回首页”同时可见。
- 首页进入学习、单词切换、反馈进入报告时不会继承旧滚动位置。
- 统计和设置页首屏展示有效信息，但允许为详细内容继续滚动。
- 所有通用 UI 继续来自 `@gotheword/pencil-pup-ui`；未在业务目录新增本地通用 UI 或第三方 UI 库。
- 后端 API、Supabase schema、学习状态和复习算法无变更。
- Chromium 与 WebKit 移动端门禁通过。
